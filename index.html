02 · best work

the one that runs itself.

One project, fully defended: problem, build, receipts. This is the thing I'd want to be interviewed about.

wildfire-risk-pipeline

● live · runs hourly · 8/8 tests passing

the problem

Wildfire risk and air quality shift hour by hour, and the raw signals — temperature, humidity, wind, PM2.5 — sit in an API nobody's watching. Useful exactly when it's fresh, useless as a one-off notebook.

the build

  1. Ingest hourly. Python pulls live weather + air-quality data for 6 US cities from the Open-Meteo REST API and lands it in a Snowflake RAW schema with defined source-to-target mappings. Raw stays immutable — every output is reproducible from source.
  2. Transform in the warehouse. Three dbt models (staging → two marts) compute a 0–100 fire-risk score and classify PM2.5 into WHO/EPA health bands. API changes get absorbed in one staging model instead of breaking everything downstream.
  3. Test everything, every run. 8 automated dbt data-quality checks (not-null, accepted-values) validate every output row. Bad data doesn't reach the analytics layer, period.
  4. Orchestrate & gate. An Airflow DAG enforces ingest → dbt run → dbt test, so transforms never touch a failed load. Docker makes the whole stack reproducible; GitHub Actions runs the test suite on every push — broken SQL can't ship.
